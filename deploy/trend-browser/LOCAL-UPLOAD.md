# 当前主方案：本地采集，服务器接收数据

用户在自己的普通 Chrome 登录 TikTok Ads，运行本项目编译的采集程序。Google / Ads 会话始终留在本机。程序只上传完整榜单、详情及媒体链接；服务器自行下载图片并保存结果，再按原时间节点写 Redis。服务器无需 Chrome、远程桌面、浏览器扩展或 Node.js。

## 服务器部署

1. 用仓库锁定的 Go 模块执行 `scripts/build-trend-clients.sh`，产生 macOS Apple / Intel、Windows x64、Linux x64 四个程序，输出到 `backend/data/trend-clients/`。也可指定单个平台，例如 `scripts/build-trend-clients.sh darwin/arm64`。没有自动安装包或拉取第三方可执行文件；按项目正常代码审核和制品发布流程发布这些程序。
2. 构建并部署原后台与前端。将上述客户端制品一并部署；后台的授权下载接口会提供对应文件。Windows 及 macOS 平台可能需要组织的签名/公证发布流程，不能要求用户绕过系统安全警告；脚本产物本身未签名。
3. 使用 `scripts/start-trend-local-backend.sh` 或 `kol-admin-trend-local.service.example` 启动现有后端。不要并行启动旧后台占用同一端口。它明确关闭服务器浏览器采集和桌面入口。
4. 配置 `trend_local.enabled: true`，持久化 `trend_local.storage_root`，将 `trend_local.client_dir` 指向构建制品目录。存储目录仅由后台用户访问。沿用已有 MySQL、Redis 和菜单迁移。
5. 通过原后台的 HTTPS 网关提供 `/api/`；上传 JSON 的网关 body 限制至少 8 MiB（建议 `client_max_body_size 9m`），上传请求被接收后异步下载图片，不需要开放 Chrome 或 VNC 端口。

既有服务器远程桌面文件留作可选历史方案，当前主方案不启用 `desktop_enabled`，不安装那些系统组件，也不加载 `nginx-desktop.conf.example`。

## 用户操作

在“资源运营 → 趋势洞察”选择时间、Tag / Video，点击“读取最新”。弹窗中的“采集地区”支持多选，默认选中页面当前地区，每批最多 5 个，地区范围与对应榜单保持一致。选择后点击“生成采集任务”，再选择本机系统、下载程序和 `trend-job-<任务ID>.json`，放在同一目录。每次任务的文件名不同，请复制弹窗中的本次命令，避免执行旧文件。例如（将占位文件名替换为实际下载名称）：

```sh
chmod +x ./kol-trend-collector-darwin-arm64
./kol-trend-collector-darwin-arm64 local-trends --job 'trend-job-<任务ID>.json'
```

普通 Chrome 144+ 中先手动登录 Ads，再在 `chrome://inspect/#remote-debugging` 启用远程调试。运行程序时核对上传目的地，输入 `yes`；按提示允许 Chrome 连接。采集完成会断开控制并保留浏览器页面，随后上传业务数据。会话失效时同样先断开，用户登录后按回车继续。

任务文件包含受限上传凭据，不要分享或提交仓库；它不包含 Google 密码或 Cookie。单地区 30 分钟，多地区按所选数量每地区预留 30 分钟，最多 150 分钟；弹窗显示准确截止时间。命令行参数和日志不打印上传凭据。后端重启会使尚未完成的内存授权失效，此时从后台重新创建任务。

多地区任务使用第 2 版任务文件，需要更新采集程序；新版同时兼容旧版单地区任务。程序复用同一个 Chrome 连接，按地区依次采集、上传并等待服务器保存完成。登录过期时才断开等待手动登录。每个地区独立更新缓存；某个地区失败继续处理后面的地区，已成功的数据保留。弹窗逐地区展示结果，全部结束后可只选择失败地区重新生成任务。主页面仍按单地区查看榜单。

本机后台支持 `http://localhost`、`http://127.0.0.1` 和 IPv6 回环地址，远程后台必须使用 HTTPS。旧版程序曾把 `localhost` 误判为无效地址并显示“任务文件无效或授权已过期”；遇到此情况需要重新下载采集程序，单独下载任务不能更新程序的校验逻辑。新版分别提示格式、地址、授权过期及时间偏差，不输出授权内容。

## 接口与数据

- `POST /business/trends/local-jobs`：现有后台登录和菜单权限下创建任务；绑定用户和筛选条件。
- `GET /business/trends/local-jobs/{job}` / `POST .../cancel`：操作者查询或取消自己的任务。
- **`POST /business/trends/local-upload?job=...&region=US`**：本地程序唯一的业务数据接收入口，使用短期 Bearer 授权，每地区 JSON 最大 8 MiB。多地区上传必须指定创建授权时绑定的地区，不能新增地区；`GET` 同一路径查询处理结果，省略地区可查询整批状态。采集失败可用 `POST` 加 `failed=1` 标记该地区失败，仅接受尚未提交的地区，不覆盖已完成结果。公网部署必须 HTTPS；不在 URL 中放凭据。
- 服务端校验 100 个唯一 ID、对应的全部详情和采集时间；相同任务重复提交相同内容返回原处理结果，不重复发布。不同内容不能复用同一个已消费授权。
- 图片仅允许既有 TikTok CDN HTTPS 域名，DNS 解析后拒绝内网/回环/保留地址，固定拨号到已校验的公网 IP，不跟随重定向。最多 1500 个去重链接、每张 5 MiB、一次最多约 256 MiB 下载量，4 路并发；不接受任意代理目标。
- 图片存储于用户私有目录，页面通过鉴权的本地媒体接口读取。下载失败保留原链接并报告失败数量，重新采集可重试过期链接。视频文件仍通过原链接播放，本次不下载整段视频。
- 结果同时保留为该用户目录内的 `dataset-<任务ID>.json`，然后原子发布到按用户/地区/时间/排序隔离的 Redis 键。Redis 仍按既有节点过期，文件不会随 Redis 过期删除。磁盘归档的保留周期由运维制定；界面不会自动把过期归档冒充最新数据。
- 失败或取消不会用部分结果覆盖旧缓存；已有图片和结果文件可以保留用于排查。不能把本地上传数据当作 TikTok 官方签名证明，它属于该用户提交的数据。

默认不进行周期采集。要更新最新内容，需要用户再次运行任务。后台窗口可收起；服务器端处理结果与原窗口无关。
