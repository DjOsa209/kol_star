# 库外 IP 推荐实现约定

状态：两轮 GrillMe 访谈后用户已确认实施。保留原框架、白色工作区与单色菜单。

## 已确认的功能

- 消歧合作语境中的 IP 与网络代理 IP；使用规范化关键词与分轮补查，输出具体 IP 候选。
- “推荐几个电竞 IP”等模糊请求先追问，每轮最多两个问题。开始研究前至少确认目标市场、合作用途与 IP 方向，预算可以待定，已有公开条件沿用。
- 被追问后明确选择“先探索”，可以在市场或用途未定时继续；仍需明确 IP 方向。不默认产品为手机。
- 电竞默认覆盖游戏 IP、赛事和战队；选手须明确需要。授权代理、营销公司属于渠道，不计入候选数量。
- 每个候选至少有名称、可核实身份、直接相关来源、理由和合作切入。授权地域、报价、档期等缺失信息明确待确认。
- 默认约 5 个，证据不足时少给。最多 3 轮、6 次基础搜索、60 秒总时限；Tavily 可一次补读最多 5 个已返回页面。
- 进度对应实际处理阶段；超时保留已核实部分和缺口，额度或模型失败停止继续补查。
- 库外候选支持来源展开、逐项补查和 2–3 个候选对比。核实入库后，才能加入正式意向或回填提需。

## 数据和实现边界

`ip_external_research.go` 负责公开研究条件整理、关键词构造、主题过滤、身份原文校验和分轮补查。检索只使用规范化公开方向、市场、用途及已验证候选名；预算、产品型号、附件和普通对话历史不外发给搜索服务。研究模型同样只收到公开研究条件与返回资料。

候选只能引用服务端返回资料的下标，模型不能新增 URL 或库内 ID。名称及包含实体类型的连续身份原文必须存在于引用来源。代理 IP、农业养殖、WIPO Lex 等负例被过滤；代理机构不能冒充 IP，来源层级不替代相关性和身份核验。WIPO 普通新闻不再误标为商标数据库。

研究条件 `externalBrief` 和结构化候选保存在原会话 JSON，复用会话归属和最多 24 条消息的保留规则。修改项目寻找条件时清除旧研究条件，避免沿用过时范围。追问提到已验证名称时，可从更早会话候选中恢复并只补查该名称；“继续深入”沿用最近一轮候选。指定名称补查按指定数量停止，不为凑满 5 个而扩展范围。模型单次调用尊重配置且最多 30 秒，同时受研究总计 60 秒限制。

检索页按用户、供应商配置、密钥散列和公开检索词缓存 15 分钟，最多 512 项，失败不缓存；模型核验与正文补读仍会执行。研究不改动库内候选或正式意向，不新增独立路由、菜单或预览页面。

右侧“库外”页签按具体候选计数。历史网页记录仍可展开，但网页条数不再充当候选数。候选以普通分隔列表展示，附对比表、研究缺口和本轮检索词。

## 验证范围

- 截图中的农业、WIPO Lex、代理广告负例：修复前失败，修复后通过。
- 自动测试覆盖追问/探索、公开条件记忆、类型排除、检索词隐私、虚构身份和无关来源拒绝、选手与代理边界、分轮/请求限制、失败停止、取消保留部分、缓存隔离与密钥轮换。
- 本地 MySQL 验证条件及候选持久化、库内结果不变和失败不保存假回答。
- 原系统 Chrome 桌面与手机验收使用明确标注的模拟候选；未使用用户密钥调用真实 Tavily。实际推荐质量仍需在已配置搜索和研究模型的环境中持续评估。
